# MergeReviewer 0.20.5

發布日期：2026-11-03。本版修正 Windows 報告發布與固定證據恢復，補齊提前檢核，並降低證據續讀與狀態查詢的往返成本。

## 本版更新

- 報告預檢與正式發布共用暫存、寫入、讀回及原子提交；暫存檔使用輸出目錄的檔案權限，既有報告不覆寫。
- 可恢復的輸出權限、占用或容量錯誤回傳 exit 3 與 `phase=publication-repair`，保留原 request、草稿、固定證據及 SHA；修復輸出後沿同一 ID 重試 finish。證據損毀仍終止，舊低階 CLI 的預設清理行為保留。
- check 與 finish 共用 Repo 關聯、finding 引用範圍及行段規則，提前攔截無證據的 related 判定、被排除 Repo 的引用及已知行數越界；發布前仍完整驗證固定證據。
- 修正長字串陣列、巢狀集合及大型字典的完成標記，所有省略內容提供續讀入口；新增有回應大小限制的 `view --requests-file` 批次唯讀續讀。
- 新增 `status --summary`，一次取得狀態、錯誤、缺口計數及下一步；capabilities 與 session 記錄技能版本、helper 摘要及 Python 版本。
- compact 草稿一次回報獨立錯誤，附確切 JSON pointer、已完成 read ID 與可引用行段。公開 v3 草稿與既有單筆介面保留。

## 驗證與範圍

- 升版前的 Windows／Python 3.14.7 完整單元測試為 374 通過、3 跳過；跳過項目為兩項受環境權限限制的 symbolic-link 案例，以及一項 POSIX 檔案模式案例。
- 自動 BDD 為 15 個情境、62 個步驟通過；28 項本機發布合約測試及 ZIP 獨立執行通過。
- 三組交錯配對的脫敏 helper 重播保留相同固定來源、返回頁面、finding 正文與缺口；工具往返每組由 24 次降為 7 次，完整驗證均為一次。配對耗時比中位數為 0.52293，只適用該互動模式；[完整驗收紀錄](../log-workflow-optimization.md)保留原始失敗、固定摘要及測量限制。
- 正式發布由同一最終 commit 的 Windows／Python 3.10、3.14 CI 驗證，並直接發布驗證過的 ZIP；GitHub Actions 證據與正式附件摘要由發布流程附於 Release。
- 模型語意品質、完整模型審查時間與原企業 runtime 的身分權限仍待另外驗收；本輪 helper 重播不代替這些門檻。Git Server 同步去重、300 秒有效期與網路配額維持既有政策。
