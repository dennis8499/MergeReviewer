# MergeReviewer 0.24.0

本版依 28 份執行紀錄改善報告閱讀、分頁操作及協定發現。活動 request 繼續使用原綁定 helper，升級後的新 request 使用新版。正式附件的來源、完整 CI 矩陣與 SHA-256 由 Release 的 Verification 收據核對。

報告保留五個主區段、每項六個工程區塊、完整證據與人工核對標記。前段新增完整性、適用版本、摘要及檢查紀錄；問題編號可導航，前兩筆證據展開，其餘收合並保留語法標示。完整固定版本表與唯一的本機路徑欄位維持工作台相容。發布時計算新版正文收據，已發布報告不重新排版。

大型 step 可回傳 `paging_requests_file`，原樣用於唯讀批次 view。投影保留 read ID／來源映射、共用正文及原 diff 行號的逐檔索引。初始狀態沒有頁面確認；接收並閱讀後才套用 delta，以 author／checkpoint CAS 保存。原始 artifact、pointer、舊陣列及 v3 草稿繼續可用。

`schema --operation author` 新增巢狀型別、引用規則與可序列化的陣列範例。遮罩保留正常識別字及連線讀取呼叫，同時處理 Bearer、Basic、認證建構式及 setter；跨行認證先分類完整來源，再選取報告行號。

實際模型試跑找出單 Repo 的 check／finish 不一致：跨 Repo 影響鏈誤填曾通過 check，卻在 finish 被當成終止錯誤。現在 author／check 提前指出 `/impact_coverage`，finish 也把這項可編輯草稿錯誤保留供同一 request 修正；immutable manifest 與固定來源錯誤仍終止，不放寬證據驗證。

安裝包包含 `capabilities.json`，由與 CLI 相同的能力描述生成回應；`tool_identity` 保存其 hash。配套 WorkflowKit launcher 在完整 binding／payload 驗證後可直接讀取此描述，省去重複 capability 子程序；舊安裝仍沿原查詢。這是已認證安裝內容的重用，不信任可編輯的 runtime 快取。

本輪增量基準固定為 commit `5a255fc9f35643eb4164fc893826cec42737ccbe` 的 0.23.0，獨立於歷史 0.20.1 正式矩陣。重播的 `--comparison-mode presentation` 驗證所有問題事實、固定引用與片段；預設 `strict` 仍比較正文。收合後來源 bytes 與完整 Markdown bytes 分列，不當作 token 或模型時間。

五組新舊模型案例的十份報告皆符合預設判準；該次原生模型審查的配對耗時比中位數為 0.84307、shell 命令比中位數為 0.88462。這批合成案例不能估計正式專案正確率或保證固定加速，工具呼叫減少 30% 的探索目標尚未達成。使用者確認示範報告的四項重點均可快速找到。

最終套件另補強認證遮罩，已完成回歸、案例來源視圖／報告內容等價核對及 helper 重測；整組模型未在此補強後重跑，模型數據歸屬於原固定候選。完整範圍、成功與失敗歷程、版本識別見 [驗證報告](../validation/review-improvements-20261117.md) 與 [驗證 JSON](../validation/review-improvements-20261117.json)。
