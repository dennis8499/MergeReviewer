# Merge Report 寫作風格

目前執行 Skill 的 agent 統一依 Codex Code Review 準則判斷問題與 P0–P3；呈現風格不重新定級。已安裝 `output-style/SKILL.md` 時依情境使用，其餘遵循本頁；固定五章、證據與人工核對契約仍保留。

## 共用 Concise 規則

- 首句陳述結論，使用繁體中文及具體行為說明影響。簡單問答一至三句；正式文件保留必要問題、缺口、證據與工程紀錄。
- 如需在 Claude Code 設定 Concise，讀取[啟用與版本指引](claude-code-style.md)；Codex 直接遵循本頁。

## Claude Code 使用 Concise

Claude Code 的設定與版本需求見[啟用與版本指引](claude-code-style.md)，不因一般審查更動使用者全域設定。

## 報告與聊天結果

標題為 `合併審查: <Repo>`，固定依序輸出五個二級章節：

1. **審查結論**：合併建議、審查狀態、具體摘要及 P0–P3 問題數量。
2. **問題總攬**：以表格列編號、優先程度、問題名稱、影響及建議處理；沒有已確認問題時直接說明。
3. **問題詳情（工程師參考）**：全數保留問題，依 P0–P3 排序。每項列問題名稱、影響、操作情境與建議處理；技術證據列觸發條件、技術觸發方式、證據說明、影響範圍、工程修正建議及固定證據。保留預期／實際結果與責任角色。新草稿標示 `report_layout="engineering-review/v1"` 並填齊操作情境、技術觸發方式、證據說明、影響範圍與工程修正建議；缺漏或填「未提供」需修正後才能發布。無標記的舊 v3 草稿維持缺少工程欄位時顯示「未提供」的相容行為。
4. **範圍與限制**：diff 起點、契約延伸狀態、已執行與未執行檢查、必要缺口、實際下一步及待人工確認項。人工紀錄保留 `merge-confirmations:start/end` 區段。
5. **技術審查紀錄（工程師參考）**：列已驗證的比較資訊、完整固定版本、逐檔覆蓋、Repo 判定、功能鏈、契約及搜尋摘要。

比較資訊包含 Repo／本機路徑、兩個輸入分支與實際 ref、commit 前 8 碼、合併方向及共同祖先到比較分支的主要差異範圍。快照列擷取起迄與全部 Repo SHA 固定時間；完整 SHA 列於固定版本紀錄。後續 ref 更新不改變本次結論。

證據只引用最小必要固定行段，附 Repo／路徑、行號、來源與完整 ref。發布器先驗證原始證據，再省略設定值與私鑰、遮蔽認證或連線內容，保留內容 SHA-256。省略內容須標明；空檔案仍標示「固定版本內容為空（0 行）」。技術搜尋紀錄只列識別、契約、固定來源、狀態及命中數，不複製原始命中內容或設定值。作者也須省略散文及標題中的機密值。

靜態推導標示「依程式推導，未實際重現」；僅有實際執行紀錄才能標示「已實際重現」。待人工確認與已確認問題分列、不計入 P0–P3；缺口或必要待確認項存在時，不能宣告通過。任何問題、限制及工程紀錄都不能因縮短報告而省略。

只發布一份 `<所選Repo>/review-reports/merge-review-<UTC時間戳>-<base前8碼>-<head前8碼>.md`，時間戳含微秒，使用固定分支頂端 SHA 並保留既有報告。draft JSON 留在 owned context，公開產出僅 Markdown。聊天另附本機報告連結與重要結果。
