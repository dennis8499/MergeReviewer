# Merge Report 寫作風格

本文件定義進度、問答及新增或更新文件的寫作規範，語言統一為繁體中文（zh-TW）。核心審查與 P0–P3 優先程度仍採 Codex 原生 Code Review。

這是單獨安裝時的原有風格。同層 `output-style/SKILL.md` 可用時，依該 Skill 的情境規則呈現；本技能的六欄問題、固定版本、待確認人工紀錄與驗證契約仍以 `workspace-review.md` 為準。

## 共用 Concise 規則

依照 [Claude Code Concise](https://code.claude.com/docs/en/output-styles#concise)，跨平台套用：

- 首句直接回答問題或陳述目前結果，省略開場、逐步旁白與收尾重述。
- 簡單問答預設一至三句；使用者要求解釋或更多細節時完整說明，正式文件不限句數。
- 在文件既有摘要或首個敘述段落交代重點，保留必要章節、欄位、證據及原始紀錄。
- 完整保留問題、缺口、限制、錯誤資訊、失敗測試輸出、安全警告與破壞性操作確認內容。

## Claude Code 使用 Concise

只有在 Claude Code 中套用本規範或處理其設定問題時，讀取
[啟用與版本指引](claude-code-style.md)。Codex 直接遵循本頁寫作規則。

## 報告與聊天結果

- 第一段直接給合併建議、審查狀態與一句具體結論。
- 結論與問題數量後列出「比較資訊」：Repo／本機路徑、分支表（角色、輸入分支、實際 ref、commit 前 8 碼）、比較分支 → 基礎分支的合併方向，以及共同祖先 → 比較分支的主要差異範圍（兩端 8 碼 SHA）。全部取自已擷取的固定證據。
- 新快照列擷取起迄時間與固定 SHA 適用範圍；後續分支更新不改變本次快照的判斷。
- 用繁體中文（zh-TW）與日常用語說明影響；必要的 API、欄位及檔案名稱可保留，幫助定位問題。
- 問題依原生 P0–P3 排序，全數保留。每項保留問題編號、優先程度與標題，正文依序使用六個欄位：**問題描述、重現原因、預期結果、實際結果、證據、建議改善方式**。
- 問題描述交代行為及影響；重現原因交代觸發條件與原因，並標明「依程式推導，未實際重現」或「已實際重現」。修正責任與選填工程細節併入建議改善方式。
- 證據只呈現能證明該問題的最小必要行段，附 Repo／路徑、行號、來源及完整固定 ref。片段由發布器從指定固定版本擷取，保留行內容與縮排；證據說明放在同一欄。空檔案標示「固定版本內容為空（0 行）」。行號與來源規則見[證據與 v3 結果契約](workspace-review.md#問題與發布)。
- 沒有問題時直接說明；不填虛構情境、空問題表或空下一步區段。下一步只列實際需要的行動，最多三項。
- 明確說明必要缺口及未執行的檢查。靜態推導不得寫成已重現、測試通過或部署安全。
- 待人工確認項與已確認問題分列、不計入 P0–P3。保留缺少證據、核對方式及可編輯的 checkbox／核對人／日期／確認結果與證據欄；完成前不宣告通過。
- 報告不輸出技術附錄。逐檔覆蓋、跨儲存庫判定、功能鏈、搜尋及完整版本紀錄保留於內部驗證；正文保留問題證據、必要缺口與未執行檢查。
- 完整程度、問題數量、優先程度及證據來自同一份驗證結果；不能為了縮短報告刪掉問題或限制。

順序：結論與問題數量 → 比較資訊 → 有問題時的詳情 → 有待確認時的疑問與人工紀錄 → 範圍與限制 → 有行動時的下一步。標題為 `Merge Report: <Repo>`，聊天回覆另附報告連結。報告僅輸出 Markdown，檔名為 `merge-review-<時間戳>-<基礎分支commit前8碼>-<比較分支commit前8碼>.md`，使用 UTC 發布時間（含微秒）及兩個固定分支頂端 SHA 的前 8 碼。
