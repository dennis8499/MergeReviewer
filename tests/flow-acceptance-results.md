# 0.18.0 三階段、多 MR 與低連線驗收

本輪比較凍結的 MergeReviewer 0.17.0 與本機 0.18.0 候選版，工作台候選版為 GitLab Workspace 0.31.0。所有遠端同步測試使用本機 Git fixture，未對使用者的 GitLab 或 Git Server 發送審查請求。

## 驗收範圍

新入口以 request ID 隔離 start／step／finish、草稿、manifest、搜尋紀錄與報告；共用的只有必要同步結果及驗證過的不可變 peer 物件。單 Repo／base／head、必要 parent、跨 Repo 契約追查、P0–P3、敏感內容處理及未完成判定沿用原有實作。

每份 start 重新固定 peer HEAD。新入口讀固定 SHA 的物件，省下 peer 工作目錄與 index 的前後掃描；擷取期間 HEAD 改變不改動當次證據，下一份請求才取得新版本。封裝、固定 refs、物件閉包、讀取、搜尋 ledger 及發布驗證保留。

## 量測方法

使用同一份既有六 Repo 靜態審查案例及固定草稿，包含五個契約、十筆讀取與十筆搜尋操作，產生六十筆 Repo 搜尋紀錄及兩項已知問題。基準使用既有批次 CLI，候選版使用 start／step／finish；每種情境前後各五次、交替順序、循序量測，與建置和測試分開執行。

冷啟動每次使用新的 runtime；暖快取先預熱；陸續啟動以獨立 request ID 沿用前一份留下的有效結果。同步中、封裝中與審查中重疊由並行測試另外驗證。效能案例使用本機分支，fetch 與網路等待均為零；網路減量由實際 fetch 次數的獨立同步測試驗證。

最後量測的前後兩版皆使用可寫的系統 Temp，避免 OneDrive 暫存檔被背景程序鎖住；六 Repo 固定來源未變更。冷啟動指應用快取為空，沒有清除作業系統的檔案快取。

每次比對完整來源 SHA／tree／inventory／指示、必要覆蓋、契約、搜尋 ledger、讀取行段、patch、實際驗證結果與問題正文。候選版 step 必須一次回傳所有必要行段與搜尋命中；需要額外 artifact 分頁的摘要不能納入本例效能結果。只省略重複本文及共同欄位，完整原始結果仍保存於 artifact。

時間包含 Python CLI 啟動及 Git 子程序，排除 fixture 建立、驗收比對及模型分析；各階段與總計分別取中位數，不能把各階段中位數相加當總計。模型分析時間保持 null。

## 模型品質界線

目前已由主要 reviewer 讀取六組來源並作已知答案的靜態檢查：無條件刪除資料的 P0、欄位相容性 P1、安全別名、最終 net-zero、必要 consumer 缺口與敏感內容。相同人工判斷分別經 0.17.0 及候選版發布驗證，核對問題、未完成與遮蔽結果。

這些是已知答案的人工檢查及機械重播，不能當作獨立模型的漏報率、誤報率或整體分析加速驗收。獨立盲測與模型時間仍未執行；本機 helper 通過不替代該項驗收。本輪也未執行 Linux／Python 3.10 的完整 runtime 矩陣或公開發布。

## 量測修正紀錄

早期版本曾出現暖快取未改善，以及完整輸出量測的冷啟動回退 8.12%。前者透過共享同輪契約讀取／patch 修正，後者移除固定 peer 不需要的工作目錄掃描及空等候狀態寫入。曾依摘要估計的大幅輸出減量已作廢；最後只計入完整行段與命中的回傳。

最後另修正強制同步的收據取用：優先使用較新的成功觀察，已知重疊 ref 的 SHA 更新即停用舊收據；同需求同步失敗也會停用舊收據，冷卻結束後不能復活舊成功結果。新案例驗證 UUID 檔名排序、force refresh、刪除分支及冷卻後重試；已固定的舊審查保持原 SHA。

一次工作台測試曾誤用正式 API 節流環境，使 mock 測試緩慢並失敗；已移除該環境設定，以隔離的測試配額重跑。一次 Python 全套測試漏設可寫網路 runtime，造成四項權限錯誤；另抓到十程序測試的摘要清理競態，已改為先取得 owner 鎖、略過活躍工作，並加入可穩定重現舊行為的回歸。修正環境及競態後重跑完整套件，最後紀錄如上。

效能工具等待測試結束後才取樣；未完成或摘要需要隱藏分頁的量測不作驗收。先前有效失敗樣本的中位數及原因保留於 JSON。
